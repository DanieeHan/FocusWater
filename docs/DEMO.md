# FocusWater 项目演示

更新：2026-10-05。

## 产品规则

- 每日目标表示当天希望累计的专注分钟；当天统计由记录日期计算。
- 水瓶是跨天保留的累计收藏。一瓶的容量在创建时采用当时的每日目标，已有进度的水瓶不会因目标修改而改变容量。
- 计时记录按活跃时间段跨日拆分，保存整分钟，保留不足一分钟的余量；手动补记按补记时刻归属日期。
- 跨日零碎分钟按最大余数分配，余数相同时归较晚一天，保存分钟总数等于累计秒数的整分钟部分。
- 修改旧瓶记录后，正在填写的最新存续瓶不改变；最新瓶完成后创建下一瓶。若最新瓶被彻底删除，则重新从剩余瓶中决定当前瓶。
- 不把计时等同于注意力检测；记录可以编辑与补记，适合自我管理。

## 两分钟演示

1. 打开“专注”，说明水瓶累计与当天统计的区别。
2. 开始、暂停、继续计时，说明暂停时间不累计。
3. 使用“补记时间”录入一段记录，观察瓶内进度；跨瓶记录会拆分，但总分钟数不变。
4. 打开“记录”，展示周趋势、搜索及编辑；使用测试数据演示，不临时删除真实记录。
5. 展示 CSV 导出和 JSON 备份入口，说明数据默认保存在本机。
6. 展示设置中的 iCloud 偏好与状态，如实说明多设备同步仍待真机验收。

## 可解释的技术点

- SwiftUI 展示界面，ViewModel 管理业务状态，SwiftData 保存记录和水瓶关系。
- 进程内使用单调时钟计算经过时间，返回前台不依赖后台每秒回调；重启恢复使用持久化状态。
- 数据保存成功后才结束当前记录；失败保留可重试的计时状态，并回滚未成功的数据库修改。
- 计时保存使用持久化凭据，避免数据库已提交而计时状态尚未清理时，重启又重复保存。
- 数据库备份、JSON 备份与 iCloud 同步的职责不同：备份提供恢复材料，同步需要额外验证账户和多设备行为。

## 本地计时逻辑检查

在项目根目录运行：

```sh
sh scripts/test-timer-accounting.sh
```

使用已安装的 Swift 编译器，直接编译生产计时逻辑并运行检查，不依赖 SwiftData 或模拟器。覆盖 12 个跨日、余秒、旧快照和夏令时场景，以及 1,000 个总时长守恒案例。这不替代整套 App 测试。旧快照没有历史时间段，兼容恢复的日期只能按原有时间锚点近似估计。

实际模型回归：`sh scripts/test-model-macos.sh`。使用已安装的 Xcode 编译器和 macOS SDK，编译生产源码及同一份 XCTest 文件，运行临时测试程序。这不等同于 iOS 真机或模拟器 UI 验收。10 月 5 日跟进已修复 `sh` 在 POSIX 模式下无法解析 Bash 语法的问题；现共 35 项通过，新增最新瓶删除回退和临时磁盘数据库重新打开测试。后者不代表旧版本数据库迁移已验收。详见 `VALIDATION_2026-10-05.md`。
